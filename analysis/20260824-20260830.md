## 一、本周先说结论

本周榜单的主角几乎都围绕 Agent 展开：有把架构图、流程图和生命周期图变成可验证产物的技能，有 GPT-Image2 提示词工程，有终端 Coding Agent，也有插件市场、科学技能、免费模型网关和本地优先工作空间。与此同时，Omarchy、OpenHuman 和 GoogleTest 说明开发者并没有放弃桌面体验、个人数据和传统工程质量。

把这些项目放在一起看，主线非常清晰：

> **AI Agent 正在从“一个能调用模型的工具”变成由 Skills、插件、上下文、模型路由和本地工作空间共同组成的软件平台。**

### 本周最明显的 5 个方向

#### 1. Agent Skills 开始进入专业工作流

archify、scientific-agent-skills 和 garden-skills 分别把架构表达、科学研究和通用生产力封装成可复用技能。开发者关注的对象正在从“哪个模型更强”转向“Agent 是否掌握一套可靠的方法”。

#### 2. 图像与界面生成正在从 Prompt 走向工程化

awesome-gpt-image-2 和 abi 都在降低视觉产物到代码或可复用模板之间的距离。提示词、案例、模板和截图到 UI 的转换，正在形成新的设计到实现工具链。

#### 3. Coding Agent 的竞争进入运行时与成本层

Codex、free-claude-code 和 freellmapi 共同说明，终端入口、模型选择、免费额度、Provider 切换和长时间运行体验，已经和模型能力一样重要。

#### 4. 插件市场正在成为 Agent 客户端的生态层

Claude 官方插件、Claude 社区插件、Cursor Plugins 以及各类 Skills 同时上榜，说明 Agent 客户端正在平台化。未来用户安装的可能不只是插件，而是一套带权限、工具和工作流的能力包。

#### 5. 本地优先与完整工作空间仍然有强需求

Omarchy、OpenLogi、OpenHuman 和 Apache Maka 都强调控制权、个人数据或完整体验。开发者想要的不只是“本地运行一个模型”，而是一个可掌控、可持续使用的工作环境。

## 二、数据怎么看：本周热度高度集中在 Agent 生态

本周 19 个项目合计增加约 **81,035 Stars**。前三名贡献约 **44.2%**，前五名约 **58.5%**，前七名约 **69.6%**，前十名约 **81.7%**。这说明热度集中度较高，但并非单一项目独占：前三名分别代表可验证架构表达、图像提示词工程和终端 Coding Agent。

### 增长最快的项目

| 排名 | 项目 | 本周增长 | 观察 |
|---|---|---:|---|
| 1 | [tt-a1i/archify](https://github.com/tt-a1i/archify) | +14.9k | Agent 开始交付可验证的工程图，而不只是文字答案 |
| 2 | [freestylefly/awesome-gpt-image-2](https://github.com/freestylefly/awesome-gpt-image-2) | +13.1k | 图像生成进入提示词、模板和案例工程化阶段 |
| 3 | [openai/codex](https://github.com/openai/codex) | +7.8k | 终端 Coding Agent 继续成为开发者工作流入口 |

这三类项目可以概括为：

> **表达层 → 执行层 → 能力资产层**

前者让 Agent 产出更可靠的工程表达，中间层让它真正进入代码库，后者则把经验和方法打包成可以复用、传播和组合的资产。

# 三、19 个热门项目逐个看

## 1. [tt-a1i/archify](https://github.com/tt-a1i/archify)

**语言：** JavaScript  
**本周增长：** +14.9k Stars  
**定位：** 生成可验证架构、工作流、时序、数据流和生命周期图的 Agent Skill

### 它是什么

archify 把软件架构表达变成 Agent 可以调用的专业技能。它关注的不只是画出一张好看的图，而是让架构、工作流和生命周期信息具备结构、验证和复用价值。

### 它能做什么

开发者可以让 Agent 根据需求或代码库生成架构图、流程图、时序图、数据流图和生命周期图，再将这些产物用于设计评审、文档维护和团队沟通。

### 核心亮点

- 覆盖多种工程图类型。
- 强调可验证与可读性。
- 将架构方法封装为 Skill，能够进入 Coding Agent 工作流。

### 谁适合用

软件架构师、后端开发者、技术负责人，以及需要维护系统文档的团队。

### 为什么值得关注

**S 级关注。**它代表 Agent 的交付物正在从代码和文字扩展到可评审的工程设计资产。

> **AI Coding 不只是“写实现”，也开始负责解释系统如何工作。**

## 2. [freestylefly/awesome-gpt-image-2](https://github.com/freestylefly/awesome-gpt-image-2)

**语言：** JavaScript  
**本周增长：** +13.1k Stars  
**定位：** GPT-Image2 的 Prompt as Code、案例与模板库

### 它是什么

这是一个围绕 GPT-Image2 的提示词工程和案例资源库，包含大量逆向分析案例、工业级模板和可转化为 Skills 的方法。

### 它能做什么

用户可以参考案例和模板完成海报、产品图、视觉设计等生成任务，也可以把提示词组织成更稳定、可重复使用的生产流程。

### 核心亮点

- 案例规模大，便于对比不同提示词策略。
- 将 Prompt 视为可版本化、可复用的代码资产。
- 从单次生成延伸到模板和 Skill。

### 谁适合用

设计师、内容创作者、产品营销团队，以及研究图像生成工作流的开发者。

### 为什么值得关注

**S- 级关注。**它的趋势价值在于提示词正在从个人技巧变成团队可复用的生产资料；实际使用仍需验证版权、模型版本和输出一致性。

> **视觉生成的下一步，是管理可复用的生成方法，而不只是写一句 Prompt。**

## 3. [openai/codex](https://github.com/openai/codex)

**语言：** Rust  
**本周增长：** +7.8k Stars  
**定位：** 运行在终端中的轻量级 Coding Agent

### 它是什么

Codex 将模型能力放进开发者熟悉的终端环境，让 Agent 可以围绕代码库理解任务、修改文件并执行开发流程。

### 它能做什么

它适合用于代码探索、实现需求、修复问题、运行测试和处理重复性的工程任务。终端形态也方便接入脚本、版本控制和现有开发环境。

### 核心亮点

- 终端优先，接近真实代码库。
- Rust 实现，强调轻量和运行效率。
- 能够与测试、Git 和其他命令行工具组合。

### 谁适合用

日常使用命令行的开发者、平台工程团队，以及希望把 Agent 接入 CI/CD 或本地自动化流程的人。

### 为什么值得关注

**S 级关注。**它是本周榜单中最典型的执行层项目：Agent 的价值最终要落到可检查、可提交、可运行的工程变更上。

> **Coding Agent 的核心不只是生成代码，而是能否在真实工程环境中完成闭环。**

# 四、把这些项目放在一起看

本周榜单可以拆成四层：

1. **表达层**：archify、awesome-gpt-image-2、abi 负责把自然语言或视觉输入转成图、图像和界面代码。
2. **执行层**：Codex、free-claude-code 和 OpenMAIC 负责让 Agent 进入终端、模型网络或多 Agent 场景。
3. **能力与生态层**：scientific-agent-skills、garden-skills、Claude Plugins、Cursor Plugins 负责把专业知识和工具变成可安装资产。
4. **运行环境层**：Omarchy、OpenLogi、OpenHuman、Maka 和 freellmapi 负责本地体验、个人数据、工作空间与模型接入。

这四层共同指向一个变化：

> **Agent 产品的基本单位，正在从“模型 + Prompt”变成“运行环境 + 模型路由 + Skills / Plugins + 可验证产物”。**

# 七、这周真正值得记住的 3 件事

### 1. Skills 正在从“Prompt 技巧”变成软件生态

科学、架构、设计、图像生成和个人生产力都开始用 Skill 组织方法。下一步竞争会集中在技能质量、来源、权限和跨客户端兼容性。

### 2. Agent 客户端正在平台化

Claude 和 Cursor 同时出现插件目录，说明客户端不再只是模型外壳，而是在争夺第三方开发者、插件分发和工作流入口。

### 3. 本地优先的价值是完整控制，而不只是隐私

本周的本地项目覆盖桌面系统、硬件、个人记忆和 Agent 工作空间。用户要的是数据、运行状态、工具和模型都能被理解与控制的完整环境。

# 八、下周继续看 Trending 时，建议重点跟踪什么

### 信号 1：插件和 Skill 是否出现跨客户端标准

关注同一技能能否在 Claude、Cursor、Codex 等环境中迁移，以及权限声明是否足够清晰。

### 信号 2：图像到代码和架构图生成是否进入验证环节

不只看生成效果，还要看输出是否可编辑、可测试、可维护，以及能否与真实项目同步。

### 信号 3：免费模型网关能否长期稳定

观察 Provider 的持续可用性、隐私策略、速率限制、模型质量和故障回退能力。

### 信号 4：个人 AI 的记忆是否可控

重点看记忆的来源、可解释性、删除机制、权限隔离和跨设备同步方式。

### 信号 5：传统工程工具是否获得新的 AI 增长

GoogleTest 这样的项目提醒我们，生成式工具越普及，测试、审计和验证基础设施越可能重新获得关注。
