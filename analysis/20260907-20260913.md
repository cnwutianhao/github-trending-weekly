## 一、本周先说结论

这周的 GitHub Trending，最值得注意的不是某一个单点项目，而是一个非常明显的**“Agent Skills 平台化”**趋势：

> **Agent 正在从“会写代码”进一步变成“按固定方法工作”，而 Skills 正在变成这套方法的分发载体。**

榜单前 15 名里，大量项目直接围绕 Agent Skills、Coding Agent 工作流、Context、架构表达和内容生成展开。与此同时，OpenMAIC、WeKnora、Text-to-CAD、Chrome DevTools MCP 又把 Agent 继续向教育、知识库、工程设计和浏览器真实环境推进。citeturn843051view0turn165598view8turn689637view7turn689637view9turn689637view10

所以，本周可以用一句话概括：

> **Agent 正从“通用能力”进入“工作方法”和“专业工作流”。**

### 本周最明显的 5 个方向

#### 1. Agent Skill 已经从“插件”变成一种软件形态

`i-have-adhd`、`Archify`、`Ponytail`、`ECC`、`diagram-design`、`humanizer`、`Superpowers`、`marketing skills`、`OpenAI Skills`、`Text-to-CAD` 等项目，本质上都在做一件类似的事情：

> 把一套原本依赖人的经验、规则和工具链，封装成 Agent 可以反复执行的能力模块。citeturn165598view0turn165598view2turn165598view3turn165598view4turn165598view5turn165598view9turn689637view0turn689637view1turn689637view4turn689637view9

这意味着以后一个优秀 Agent 的能力，很可能不只是模型本身，而是：

`Model + Skills + Tools + Context + Workflow`

#### 2. AI Coding 正在从“生成代码”走向“执行工程流程”

本周 `Ponytail`、`ECC`、`Superpowers`、`Spec Kit`、`Context Mode`、`Chrome DevTools MCP`、`FirstMate`、`Worktrunk` 几乎把 AI Coding 的整个链路拼了出来：

```text
需求
 ↓
规格
 ↓
计划
 ↓
并行 Agent
 ↓
编码
 ↓
测试
 ↓
浏览器 / 运行环境验证
 ↓
Review
 ↓
合并
```

这已经不是传统意义上的 Copilot 了，而是在向 **Engineering Agent** 演进。citeturn689637view0turn689637view2turn593771search0turn689637view10turn689637view11turn689637view12

#### 3. Context 已经成为 Agent 的核心基础设施

`Context Mode` 解决的是工具输出、Session continuity 和上下文压缩；`WeKnora` 解决知识和 RAG；`humanlayer/skills` 与 `OpenAI Skills` 则进一步把能力本身变成可发现、可组合的模块。

换句话说：

> Agent 的下一场竞争，不只是“上下文窗口有多长”，而是“哪些信息值得进入上下文、什么时候进入、进入之后如何持续使用”。citeturn593771search0turn689637view7turn689637view4

#### 4. AI 生成的边界继续向“可视化内容”和“专业工具”扩张

`Hyperframes` 把 HTML 直接变成视频；`diagram-design` 把技术内容变成专业图表；`Text-to-CAD` 把自然语言推进到 CAD / CAE / CAM。

这意味着：

> Agent 开始从“写文本 / 写代码”，进入“生成专业数字资产”。citeturn165598view6turn165598view5turn689637view9

#### 5. Human-in-the-loop 与 Agent Team 开始成为常态

`FirstMate` 的定位非常直接：“Talk to one agent. Ship with a crew.”；`OpenMAIC` 则把多个 AI 角色组织成课堂；`Superpowers` 也明确使用 subagent-driven development。

这说明多 Agent 的重点正在从“数量”转向：

> **角色分工、上下文传递、验证和协作边界。**citeturn689637view11turn165598view8turn689637view0

## 1. ayghri/i-have-adhd

语言：Python

本周增长：+15.9k Stars

定位：极简、可执行的 Coding Agent 输出 Skill

### 它是什么

`i-have-adhd` 是一个给 Coding Agent 使用的 Skill，目标非常明确：

> 不要把真正答案埋在一大段废话里。

它要求 Agent 直接给出下一步动作、编号步骤、当前状态和一个明确的后续行动。仓库还为 Claude Code、Codex、Cursor、OpenCode 等不同 Agent 环境准备了插件和 Skill 结构。citeturn165598view0

### 它能做什么

它会强制 Agent：

- 先说下一步做什么
- 多步骤任务使用编号
- 减少无关背景
- 不用冗长结尾
- 保持当前状态清晰

### 核心亮点

- 规则非常简单。
- 直接影响 Agent 的交互体验。
- 有 Evals / Tests。
- 多 Agent Harness 兼容。

### 谁适合用

- 高频 Coding Agent 用户
- 不喜欢 AI 废话的人
- IDE / CLI Agent 用户
- 团队 Agent 标准化场景

### 为什么值得关注

**S+ 级关注。**

因为它体现了一个很容易被忽视的问题：

> **模型越强，不代表交互越高效。**

未来 Agent 的竞争除了“做事能力”，还会包括“怎么和人高效协作”。

## 2. bilawalsidhu/gods-eye-view

语言：JavaScript

本周增长：+10.5k Stars

定位：真实数据驱动的 3D 空间情报浏览器

### 它是什么

God's Eye View 是一个运行在浏览器里的 3D 空间智能平台。

它不是简单的地球仪，而是把真实公开数据放到可交互的三维地球上，用于观察地理、交通、卫星或开放空间数据。

### 它能做什么

核心体验是：

> 浏览真实世界，而不是浏览网页。

用户可以在 3D 地球上查看不同类型的数据层，结合时间、地点和空间关系进行探索。

### 核心亮点

- Photorealistic 3D Globe。
- Real-world data。
- 浏览器直接运行。
- 空间信息可视化。

### 谁适合用

- GIS 开发者
- 数据可视化工程师
- 地理信息研究者
- 想研究 Spatial AI 的开发者

### 为什么值得关注

**S 级关注。**

它和本周 Agent 项目看起来毫无关系，但其实代表另一条重要路线：

> **AI 正在从“理解文本”走向“理解真实空间”。**

未来 Agent 很可能不只操作文件，还会操作地图、设备和真实世界数据。

## 4. DietrichGebert/ponytail

语言：JavaScript

本周增长：+9.3k Stars

定位：减少 AI Coding Agent 的代码量和复杂度

### 它是什么

Ponytail 的理念很简单：

> 最好的代码，是你根本没有写的代码。

它试图让 Agent 像一个经验丰富、尽量不折腾的高级工程师一样工作。

### 它能做什么

主要帮助 Agent：

- 减少无必要代码
- 避免过度抽象
- 控制 diff
- 优先选择简单方案
- 少做无关重构

### 核心亮点

- “Less code” 变成明确原则。
- 支持多个 Agent 环境。
- 非常适合作为 Agent Harness 的行为约束。

### 谁适合用

- Coding Agent 重度用户
- 软件工程团队
- 对 AI 过度实现敏感的人

### 为什么值得关注

**S+ 级关注。**

因为它把 AI Coding 的评价标准从：

> “写了多少？”

转向：

> **“少改多少还能把事情做好？”**

这是一种非常成熟的工程视角。citeturn165598view3
