## 一、本周先看结论

这周最值得注意的，不是又出现了几个“更大的模型”，而是 AI 正在往**执行层**移动。

过去更常见的是：

```text
用户 → AI → 答案
```

这周的热门项目更接近：

```text
用户
  ↓
Agent
  ↓
工具 / 浏览器 / 代码库 / 文档 / GIS / CAD / 3D
  ↓
执行
  ↓
结果
```

18 个项目里，AI Agent、AI Coding、Agent Skill、AI 基础设施占据了非常明显的位置；与此同时，P2P / Mesh 通信、3D 内容生成、GIS、建筑设计等项目也在上涨。换句话说，**AI 正从“聊天能力”变成“进入真实工作流的能力”。**

### 本周最明显的 5 个方向

| 方向 | 代表项目 | 这意味着什么 |
|---|---|---|
| AI Agent | Buzz、Ego-lite、OpenWork | AI 开始进入真实执行环境 |
| AI Coding | Open Code Review、JCode、T3 Code | AI 逐渐参与整个开发流程 |
| Agent Skills | i-have-adhd、book-to-skill、Text-to-CAD | “能力”开始被做成可复用模块 |
| AI 基础设施 | OmniRoute、AIsuite | 多模型、路由、工具调用正在基础化 |
| 新型交互 / 专业软件 | BitChat、GeoLibre、TRELLIS.2、Pascal Editor | AI 之外，开发者也在重新探索设备、空间和专业工作流 |

## 二、18 个热门项目逐个看

> 评价中的“值得关注”不是项目质量评分，而是从**普通开发者、AI 开发者和技术研究者**角度判断“有没有必要花时间了解”。

## 1. [block/buzz](https://github.com/block/buzz) —— 让人和 Agent 在同一个工作空间里协作

**榜单表现**：Rust，20.9k ⭐，本周 +9.0k

### 它是什么

Buzz 是一个可以自托管的协作工作空间，把**人、AI Agent、代码、工作流和项目事件**放进同一个空间。底层采用事件日志和身份体系，让人和 Agent 都成为工作空间中的“成员”。

### 它能做什么

你可以把它理解成“面向 Agent 时代的团队协作空间”：

- 让 Agent 加入频道、读取上下文并执行任务
- 把代码分支、补丁、CI、Review、合并决策放到同一个房间
- 让 Agent 搜索历史讨论、代码和工作流记录
- 用工作流触发消息、Webhook、定时任务等自动化动作
- 自建 relay，掌握自己的数据和协作环境

### 核心亮点

1. **Agent 不是外挂机器人，而是协作空间里的正式成员。**
2. 人、Agent、Git 事件、工作流都可以进入同一个事件日志和检索体系。
3. 支持自托管，强调身份、审计和数据主权。
4. 已经开始提供面向 Agent 的 CLI / harness，方便 Codex、Claude Code 等接入。

### 谁适合用

AI Agent 平台开发者、想做多 Agent 协作的人、研发团队，以及关心私有化和数据主权的团队。

### 值得关注吗？

**★★★★★**

它真正有意思的地方不是“又做了一个聊天工具”，而是它在尝试回答一个更大的问题：**如果 Agent 真的是团队成员，团队协作软件应该长什么样？**

## 2. [OmniRoute](https://github.com/diegosouzapw/OmniRoute) —— 给各种 AI 工具提供统一入口

**榜单表现**：TypeScript，37.6k ⭐，本周 +7.3k

> 榜单链接显示为 `sponsors/diegosouzapw`，实际热门项目是其 OmniRoute 项目。

### 它是什么

OmniRoute 是一个 AI Gateway：把多个模型和服务商放在一个统一入口后面，让 Claude Code、Codex、Cursor、OpenCode、Cline 等客户端通过一个兼容接口访问不同模型。

### 它能做什么

- 统一接入不同 LLM 提供商
- 根据模型 / 配额 / 失败情况做路由和 fallback
- 让不同 Coding Agent 复用同一个网关
- 管理多模型调用和成本
- 配合 MCP / A2A 等 Agent 协议扩展工作流

### 核心亮点

1. **统一入口**：客户端不用为每一家模型服务单独做适配。
2. **路由与故障切换**：可以把“模型选择”从业务代码里抽出来。
3. **开发者工具友好**：面向 Claude Code、Codex、Cursor 等真实工作流。
4. 榜单项目简介强调大量 provider / model 覆盖，说明它解决的是“模型太多”的工程问题，而不只是调用某一家 API。

### 谁适合用

经常切换模型的开发者、AI Agent 开发者、需要统一管理 API 的团队、希望把模型供应商和业务逻辑解耦的人。

### 值得关注吗？

**★★★★★**

如果未来应用不再只绑定一家模型，那么 **AI Gateway 很可能会像数据库连接池、API Gateway 一样成为常见基础设施。**

## 3. [permissionlesstech/bitchat](https://github.com/permissionlesstech/bitchat) —— 不依赖中心服务器的聊天

**榜单表现**：Swift，34.1k ⭐，本周 +5.7k

### 它是什么

BitChat 是一个以 **Bluetooth Mesh** 为核心的去中心化聊天项目，风格接近 IRC，但重点是设备之间直接通信，而不是先连接到中心服务器。

### 它能做什么

- 附近设备之间直接聊天
- 没有互联网时依然可以在一定范围内通信
- 节点可以通过 Mesh 方式转发消息
- 在 Bluetooth 不可用时，项目还提供基于 Nostr 的后备传输
- 消息可排队，等可用传输恢复后再发送

### 核心亮点

1. **设备到设备通信**，不是传统的“客户端 → 云服务器”。
2. Mesh 可以让消息经过其他节点继续传播。
3. 同时探索 Bluetooth、本地通信和 Nostr relay 的组合。
4. 它不是纯概念项目，而是一个可运行的移动端应用。

### 谁适合用

移动端开发者、网络协议爱好者、边缘计算 / P2P 研究者、对离线通信和隐私有需求的人。

### 值得关注吗？

**★★★★★**

它的价值不在于取代微信，而在于重新提醒开发者：**“必须联网 + 必须有中心服务器”并不是所有通信产品的唯一答案。**

## 4. [ayghri/i-have-adhd](https://github.com/ayghri/i-have-adhd) —— 给 Coding Agent 加一套更容易执行的输出规范

**榜单表现**：Python，15.6k ⭐，本周 +5.2k

### 它是什么

这是一个 Agent Skill / 插件，用来改变 Coding Agent 的回答方式：**先给下一步动作、步骤编号、减少废话、减少上下文丢失**，让输出更容易直接执行。

### 它能做什么

例如把：

> “先分析一下你的认证流程……”

变成：

> “先执行 `npm install ...`，然后修改 `src/auth.ts:42`。”

也就是把 AI 的“说明能力”进一步变成“执行指令能力”。

### 核心亮点

1. 强制答案和下一步动作前置。
2. 多步骤任务使用明确编号。
3. 强调状态延续、减少跑题和无关背景。
4. 可以作为 Claude Code、Codex、Copilot、Cursor 等 Agent 工作流中的 Skill。

### 谁适合用

每天大量使用 Coding Agent 的开发者；尤其适合觉得 AI 经常“讲很多，但没有直接告诉我下一步做什么”的人。

### 值得关注吗？

**★★★★☆**

项目本身技术门槛不高，但它暴露了一个非常重要的问题：**Agent 的生产力不只取决于模型 IQ，也取决于输出格式和交互协议。**

## 5. [virgiliojr94/book-to-skill](https://github.com/virgiliojr94/book-to-skill) —— 把技术书变成 Agent 的长期知识

**榜单表现**：Python，15.2k ⭐，本周 +5.1k

### 它是什么

book-to-skill 可以把 PDF、EPUB、文档目录甚至一组资料转换为 Agent Skill，让 Claude Code、GitHub Copilot CLI、Amp 等 Agent 按需加载知识。

### 它能做什么

比如你有一本 800 页的计算机技术书，不必每次把整个 PDF 丢给模型，而是把它整理成：

- 核心概念
- 章节索引
- glossary
- patterns
- cheatsheet
- 章节文件

Agent 需要某个主题时再加载对应内容。

### 核心亮点

1. **把“知识库”转换成 Agent 原生可用的 Skill。**
2. 按章节按需加载，减少一次性塞进上下文的内容。
3. 从“总结一本书”转向“让 Agent 能长期使用一本书”。
4. 不只适用于书，也能处理文档和资料集合。

### 谁适合用

研究人员、学生、技术专家、需要让 Coding Agent 长期参考内部技术文档的人。

### 值得关注吗？

**★★★★★**

它代表的趋势非常明确：**Agent 的下一场竞争可能不仅是模型能力，而是“知识如何结构化并长期可调用”。**

## 6. [alibaba/open-code-review](https://github.com/alibaba/open-code-review) —— AI 正式进入 Code Review

**榜单表现**：Go，17.8k ⭐，本周 +4.7k

### 它是什么

Open Code Review 是阿里开源的 AI Code Review CLI。它读取 Git diff，再让具备工具调用能力的 Agent 深入理解代码库，最后产生行级的结构化审查意见。

### 它能做什么

- 审查 Git diff
- 对问题定位到具体代码行
- 读取完整文件和相关代码上下文
- 检查 Bug、安全、性能和代码质量问题
- 对整个目录执行扫描，而不仅是某一次 diff
- 接入 CI/CD 自动做代码审查

### 核心亮点

1. **不是简单把 diff 扔给模型，而是让 Agent 主动读代码库。**
2. 支持行级审查意见，更接近传统 Review 的使用体验。
3. 有确定性规则 + LLM Agent 的混合架构。
4. 已经被用于大规模研发场景。

### 谁适合用

后端开发者、企业研发团队、代码质量平台建设者、需要自动化 PR / MR Review 的团队。

### 值得关注吗？

**★★★★★**

AI Coding 最重要的变化之一，就是从“帮我写代码”走向“**帮我负责软件生命周期中的其他环节**”。Code Review 正是其中非常现实的一步。

## 7. [citrolabs/ego-lite](https://github.com/citrolabs/ego-lite) —— 让 Agent 使用你的真实浏览器

**榜单表现**：JavaScript，7.6k ⭐，本周 +4.1k

### 它是什么

Ego Lite 是面向 AI Agent 的浏览器，核心思路是：**你和 Agent 可以共享真实浏览器环境，同时互不干扰。**

### 它能做什么

- 让 Agent 自动浏览网页
- 执行网页操作和自动化任务
- 复用你已经登录的浏览器状态
- 让多个 Agent 在独立 Space 中执行任务
- 避免传统 browser automation 频繁重新登录、抢同一个浏览器标签页

### 核心亮点

1. Agent 使用的是“真实浏览器工作环境”，不是另开一套完全隔离的浏览器。
2. 登录状态可以直接成为 Agent 的工作上下文。
3. 多个 Agent 可以并行执行不同浏览任务。
4. 把 Browser 从“被控制的工具”变成 Agent 的工作空间。

### 谁适合用

Browser Agent 开发者、自动化测试人员、做网页信息采集 / 后台操作 / RPA 的开发者。

### 值得关注吗？

**★★★★★**

Agent 如果真的要替人完成工作，就必须进入浏览器；因此 **Agent Browser 很可能会成为 Agent 基础设施中的一个独立层。**

## 8. [1jehuang/jcode](https://github.com/1jehuang/jcode) —— 更省内存的 Coding Agent Harness

**榜单表现**：Rust，15.2k ⭐，本周 +3.5k

### 它是什么

JCode 是面向 Coding Agent 的轻量级 harness，重点不是“再造一个模型”，而是**降低运行 Agent 本身的资源消耗**。

### 它能做什么

- 运行 Coding Agent 工作流
- 管理多会话开发
- 在本地机器上以更低的 RAM 占用运行 Agent
- 把性能和启动速度作为一等指标

### 核心亮点

1. 明确把 **RAM / 启动速度 / 多会话效率** 作为核心卖点。
2. Rust 实现，更偏底层工具路线。
3. 适合需要长期运行多个 Agent Session 的场景。
4. 说明 Coding Agent 生态正在从“模型工具”进入“运行时工具”阶段。

### 谁适合用

高频使用 Coding Agent 的开发者、喜欢本地工具链的人、资源有限但需要多 Agent 并行的人。

### 值得关注吗？

**★★★★☆**

它的意义在于：**当 Agent 数量增加以后，Agent Runtime 的资源效率本身就会变成问题。**

## 9. [moeru-ai/airi](https://github.com/moeru-ai/airi) —— 一个可以“生活”起来的 AI Companion

**榜单表现**：TypeScript，46.5k ⭐，本周 +3.3k

AIRI 是一个开源、自托管的 AI Companion / 虚拟角色项目，目标接近“开源版 Neuro-sama / Grok Companion”。它把聊天、实时语音、Live2D / VRM、游戏交互等能力放到一个持续存在的数字角色里。

### 它能做什么

- 实时语音聊天
- 运行虚拟角色 / Live2D / VRM
- 与 Minecraft、Factorio 等游戏交互
- 在桌面或 Web 环境长期运行
- 接入不同 LLM 和本地模型相关技术栈

### 核心亮点

1. **不是聊天机器人，而是一个持续存在的数字角色。**
2. 同时涉及 LLM、语音、视觉、动画、WebGPU、游戏自动化等多个技术栈。

4. 自托管意味着用户可以真正拥有这个数字角色。

### 谁适合用

AI Companion / VTuber 开发者、前端和图形技术开发者、语音交互研究者、想研究“具身化 AI 角色”的人。

### 值得关注吗？

**★★★★☆**

它未必是所有开发者都会使用的工具，但它代表了一个方向：**AI 不一定只是一个窗口里的聊天框，也可以成为长期存在、能看、能听、能行动的数字角色。**

## 11. [pascalorg/editor](https://github.com/pascalorg/editor) —— 浏览器里的 3D 建筑编辑器

**榜单表现**：TypeScript，20.7k ⭐，本周 +3.0k

Pascal Editor 是一个基于 React Three Fiber 和 WebGPU 的 3D 建筑编辑器，用于创建和分享建筑项目。

### 它能做什么

- 在浏览器里编辑 3D 建筑场景
- 创建和修改空间 / 几何元素
- 在线预览和分享项目

### 核心亮点

2. 把传统需要本地专业软件才能做的 3D 编辑部分搬到 Web。
3. 项目结构本身也适合研究 3D 编辑器架构。
4. 和 AI 项目一起进入榜单，说明“AI + 专业 3D 工具”的组合值得继续观察。

### 谁适合用

Web 3D 开发者、建筑可视化开发者、数字空间产品开发者、想研究浏览器 3D 编辑器的人。

### 值得关注吗？

**★★★★☆**

它本身不完全是 AI 项目，但它提醒我们：**下一代专业软件很可能同时具备 Web、3D 和 AI 三个属性。**

## 12. [opengeos/GeoLibre](https://github.com/opengeos/GeoLibre) —— 把 GIS 变成跨平台工作空间

**★★★★☆**

如果你从软件工程角度看，它很有代表性：**专业科学软件正在向浏览器、本地计算和跨平台统一工作空间迁移。**

## 13. [different-ai/openwork](https://github.com/different-ai/openwork) —— 开源版 Claude Cowork / Codex 工作台

**榜单表现**：TypeScript，20.2k ⭐，本周 +2.7k

OpenWork 是一个开源桌面应用 / 工作空间，用于分享 AI Workflow，并作为 Claude Cowork、Codex 一类产品的开源替代方案。

### 它能做什么

- 给 AI Agent 提供专门的工作空间
- 复用 Skills、MCP 和连接的服务
- 把 Agent 能力分享给团队成员
- 管理不同项目、工作区和 Agent 能力
- 与 OpenCode 等工具配合

### 核心亮点

1. **不是单纯聊天界面，而是 Agent 工作空间。**
2. Skills / MCP 可以成为可复用的团队资产。
3. 同时面向个人开发者和团队。
4. 开源替代商业 Agent Workspace，是一个很明确的产品方向。

### 谁适合用

AI Coding 重度用户、希望共享 Agent 能力的团队、想研究“Agent 操作系统 / 工作台”形态的人。

### 值得关注吗？

**★★★★★**

这类工具真正解决的是“**我已经有很多 Agent 能力，怎么组织、复用和分享？**”——这很可能成为下一阶段 AI 开发工具的核心问题。

## 14. [earthtojake/text-to-cad](https://github.com/earthtojake/text-to-cad) —— 让 Agent 真正进入 CAD / 机器人 / 硬件设计

**榜单表现**：JavaScript，12.5k ⭐，本周 +2.0k

### 它是什么

这个项目更准确地说是一个 **CAD / Robotics / Hardware Design 的 Agent Skills 库**，不是单纯“文本生成 CAD 模型”。它给 Coding Agent 提供生成、检查、查找和交付 CAD / 机器人描述文件的能力。

### 它能做什么

- 用自然语言或代码 Agent 创建 / 修改 CAD
- 导出 STEP、STL、3MF、DXF、GLB 等格式
- 生成 URDF / SRDF / SDF 等机器人描述
- 查找常用标准件 / STEP 零件
- 通过可视化工具检查生成结果

### 核心亮点

1. **把 Agent 从“代码世界”带进物理设计世界。**
2. 不只是生成模型，还覆盖 Review、Export、Reference、Source 等工作流。
3. 对机器人设计特别友好，能连接 CAD、URDF、仿真等环节。
4. 设计过程强调“源文件优先，再生成派生文件”，更符合工程实践。

### 谁适合用

机械工程师、机器人开发者、硬件创业团队、CAD 开发者、对 AI + Engineering 感兴趣的人。

### 值得关注吗？

**★★★★★**

这是本周我最建议机械 / 机器人方向开发者关注的项目之一：**AI Coding 下一步很可能不只生成代码，而是直接生成可制造、可仿真的工程资产。**

## 17. [microsoft/TRELLIS.2](https://github.com/microsoft/TRELLIS.2) —— 高保真的图像到 3D 生成

## 四、这周真正值得记住的 6 个变化

### 1. Agent 正在从“功能”变成“工作主体”

Buzz、OpenWork、Ego-lite、JCode 都在解决同一个问题：**怎么让 Agent 长时间工作，而不是只在聊天框里回答一句话。**

### 2. Coding Agent 开始覆盖整个软件生命周期

从写代码，到 Review、测试、CI、工作流、发布，AI 正在从“代码生成器”扩展成“研发执行层”。

### 3. Agent Skill 正在变成一种新的软件分发方式

`i-have-adhd`、`book-to-skill`、`text-to-cad` 的共同点是：把一组能力封装成 Skill，再交给不同 Agent 使用。

这意味着未来软件可能不只是安装一个 App，而是：

```text
Agent
 +
Skills
 +
MCP
 +
Tools
 +
Knowledge
```

### 4. AI 基础设施开始“去厂商绑定”

OmniRoute 和 aisuite 都在做多模型统一接入，只是一个更偏 Gateway，一个更偏 SDK / Agent API。

这会越来越重要，因为模型更新速度已经快到：**把应用和某一家模型深度绑定，技术债会非常明显。**

### 5. Agent 正在向现实世界的专业工具渗透

Text-to-CAD、TRELLIS.2、Pascal Editor、GeoLibre 说明一个变化：

```text
AI
 ↓
文字 / 代码
 ↓
浏览器 / 软件
 ↓
CAD / GIS / 3D / 空间
 ↓
现实世界
```

AI 的价值边界正在向“可执行的专业工作”延伸。

### 6. P2P / 本地计算并没有消失

BitChat 和 GeoLibre 代表另外一条路线：**不是所有数据都应该上云，不是所有设备都必须依赖中心服务。**

当 AI、边缘计算和隐私需求继续增长，本地计算、本地数据、本地通信依然会是重要方向。

---

## 五、最终判断：这一周 GitHub 在告诉我们什么？

如果只看 Star，很容易得到一个结论：

> “AI 还是很火。”

但如果把 18 个项目放在一起看，真正的变化其实是：

> **AI 开始从“模型能力”向“执行能力”迁移。**

过去大家关心：

> 哪个模型更聪明？

现在越来越多的人关心：

> 能不能帮我打开浏览器？
> 能不能帮我改代码？
> 能不能帮我 Review？
> 能不能记住一本书？
> 能不能直接画 CAD？
> 能不能生成 3D？
> 能不能进入我的团队？
> 能不能在本地工作？

因此，本周最值得关注的并不是某一个模型，而是围绕 Agent 形成的一整层新的软件栈：

```text
                    人
                    │
             Agent / AI Worker
                    │
       ┌────────────┼────────────┐
       │            │            │
     Skills       Tools       Knowledge
       │            │            │
       ├──── Browser / Code / CAD / GIS ────┤
                    │
               Runtime / Gateway
                    │
              Models / Providers
```

**这可能才是这一周 GitHub Trending 最值得记录的东西：AI 正在从一个“产品功能”，慢慢变成一层新的软件基础设施。**
